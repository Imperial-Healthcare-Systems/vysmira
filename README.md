# VYSMIRA Solutions — Next.js

Next.js 15 (App Router, TypeScript) port of `../vysmira-preview.html`.

## Run

```bash
npm install
npm run dev        # http://localhost:3000
npm run build && npm run start
```

## How the port works

The single-file build stays the source of truth. `npm run generate` reads
`../vysmira-preview.html` and rewrites the app from it:

| Source in the HTML | Becomes |
| --- | --- |
| 34 `<div class="view" id="v-…">` blocks | one route each — `app/**/page.tsx` (`v-404` → `app/not-found.tsx`) |
| each view's `data-title` | that route's `metadata.title` |
| `<style>` design system | `app/globals.css` |
| behaviour `<script>` | `public/site.js` |
| hash router `<script>` | dropped — Next routing replaces it |
| header / mobile nav / footer / sticky CTA | `components/chrome.ts`, rendered by `app/layout.tsx` |
| `<script type="application/ld+json">` | `components/ldjson.ts` |
| inlined base64 images | `public/img/asset-*.{png,jpg}` |
| files in `../img/` | copied to `public/img/` as-is |
| `href="#/services/rpo"` | `href="/services/rpo"` |

Art that isn't inlined lives in `Downloads/Vysmira/img/` next to the HTML, and
is referenced from CSS with a **relative** path (`url("img/hero-team.jpg")`) so
the standalone preview still works over `file://`. The generator copies those
files into `public/` and rewrites the CSS to `url("/img/hero-team.jpg")`.

Page markup is injected verbatim via `dangerouslySetInnerHTML`, so the original
CSS class names and DOM structure are untouched and the design cannot drift.
Everything prerenders as static HTML.

Two things the generator patches, both because the chrome now survives
navigation instead of being re-rendered on every hash change:

- `boot()` is split into once-only chrome setup (`initHeader`, `initMegaMenus`,
  `initMobileNav`, `initMobileCta`) plus a re-runnable `initPage()` (reveals,
  counters, form validation). Re-running the whole thing would stack duplicate
  listeners on the header.
- `components/NavEnhancer.tsx` intercepts clicks on internal `<a href="/…">` in
  the raw-HTML chrome and turns them into client-side navigations, then closes
  any open mega menu / mobile nav and scrolls to top on route change.

**Edit the HTML, then re-run `npm run generate`.** Files marked
`GENERATED by scripts/generate.mjs` are overwritten — the generator also deletes
every directory under `app/` first, so route removals propagate. Hand-written
files: `app/layout.tsx`, `components/PageBody.tsx`, `components/NavEnhancer.tsx`,
`scripts/generate.mjs`.
